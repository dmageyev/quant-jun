# Module 01 — Foundations of Quant Mindset

## Learning outcomes

Після модуля студент вміє:

1. Пояснити різницю між intuition-driven та data-driven рішеннями.
2. Описати базовий quant pipeline: data → feature → rule → evaluation.
3. Порахувати просту денну дохідність за рядом цін.

---

## 🔍 Аналогія

Уяви, що ти тренер команди: інтуїція підказує, хто сильний, але справжню картину дає статистика матчів.  
У quant-підході ринок — це "команда", а дані — це таблиця результатів, без якої рішення часто випадкові.

## 🏗 Архітектурна суть

**Quant mindset** — це цикл рішень, де гіпотеза перевіряється на даних:

1. **Data acquisition** — отримуємо ціни/обсяги.
2. **Preprocessing** — перевіряємо пропуски, аномалії, частоту даних.
3. **Feature extraction** — будуємо сигнали (returns, volatility, moving averages).
4. **Rule / hypothesis** — формалізуємо правило прийняття рішень.
5. **Evaluation** — перевіряємо результат на історії й ризик.

Ключова ідея: якщо крок не можна відтворити, він не придатний для робочого quant-процесу.

## ⚙️ Практична перевірка

1. Візьми ряд цін `P = [100, 101, 99, 102]`.
2. Порахуй денні simple returns за формулою  
   `r_t = (P_t - P_{t-1}) / P_{t-1}`.
3. Визнач:
   - скільки було позитивних днів,
   - середню денну дохідність.

Перевірка себе:
- `r2 = 1.00%`
- `r3 ≈ -1.98%`
- `r4 ≈ 3.03%`

## 🔐 Важливий момент

- Не плутай **price level** і **return**: моделі та порівняння зазвичай роблять по returns.
- Не інтерпретуй 2–3 точки даних як "стратегію": потрібна довша історія та out-of-sample перевірка.
- Data leakage (використання майбутньої інформації) робить результати фальшиво хорошими.
